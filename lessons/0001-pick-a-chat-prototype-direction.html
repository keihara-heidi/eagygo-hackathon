Lesson 0001 · KICK Hackathon

Picking a chat prototype direction

~5 minutes · Serves the mission: choose a direction you can defend to judges · Cheat sheet: KICK chat data

You have four candidate directions and about six hours. This lesson gives you the frame for choosing between them — then walks each option through that frame. The win: you leave able to say "we chose X because…" in one breath, which is exactly what the presentation demands.

The skill: four lenses

Every hackathon option can be scored against the brief itself, using four lenses:

  • Loop — is it genuinely two-way? The brief twice demands "a genuine feedback loop" and warns against "a one-way display." The loop must be visible, not implied.
  • Demo — is the idea obvious in under two minutes on a projector? The brief says a strong submission makes the idea obvious that fast.
  • Fit — which judging weights does it harvest? Problem Solving 25% + Creativity 25% reward the idea; Technical Execution is only 20%. Idea quality beats tech depth.
  • Clock — can it be demoable by ~3:30 PM with mocks? Only committed code counts.

Rule of thumb: maximise loop visibility per build hour.

The options, through the lenses

A — Chat Pulse · streamer insights dashboard

A live dashboard: sentiment gauge, hype graph, trending emotes and keywords, top chatters by badge.

Loop
Streamer sees chat → reacts on stream → chat reacts. Real, but indirect — on screen it looks one-way.
Signals
content, emotes[], sender.identity.badges[], created_at rate.

Pros

  • Matches the "insights" framing directly
  • Lots of pretty surface area
  • Easiest to mock convincingly

Cons

  • The trap: reads as a one-way display
  • Judges have seen a thousand dashboards
  • Loop needs a bolt-on to count

Pick this if your team's strength is data-viz and you can add a viewer-facing element to close the loop.

B — Hype Meter · viewer-driven overlay

Emote and command spam charges an on-stream meter; hitting the threshold fires an overlay event and a bot message in chat.

Loop
Viewers act → overlay reacts instantly → streamer reacts → viewers see it. Tight and visible.
Signals
emotes[] density, message rate, kicks.gifted as a boost.

Pros

  • Fastest to build — one surface, one state
  • Obvious in 30 seconds
  • Closed loop out of the box

Cons

  • Known pattern — creativity risk
  • Thin on the "insights" half of the brief

Pick this if the clock is your binding constraint and you want maximum polish on a single loop.

C — Polls & Predictions bot · chat-native participation

The streamer poses a question; viewers vote with chat commands or emotes; the bot replies with results, threaded via reply_to_message_id.

Loop
Fully closed, both directions, inside chat itself — the literal "chat talks back".
Signals
Command keywords in content, emote votes; POST /public/v1/chat for the write-back.

Pros

  • The most genuinely two-way option
  • Exercises the write API, not just reads
  • Viewers participate directly

Cons

  • Every team's first idea — needs a twist for the 25% creativity mark
  • Chat-only UI is less visual on stage

Pick this if you have a distinctive twist (prediction streaks, viewer-versus-viewer brackets) and a chat-native demo plan.

D — Chat Shapes the Stream · write-API novelty

The trending keyword or emote rewrites the live stream title; crossing a hype threshold auto-creates a channel-point reward — "Chat unlocked: this."

Loop
Chat talks → the stream itself changes → viewers see their mark on the channel.
Signals
Keywords, emotes[]; channel:write + channel:rewards:write scopes.

Pros

  • Highest novelty — uses write surfaces other teams won't touch
  • Great narrative: chat literally talks back

Cons

  • A title change is subtle on a projector
  • Rewards need channel context to feel real
  • Slower burn — hardest two-minute demo

Pick this if you're confident presenters chasing the creativity axis over demo flash.

The hybrid — Hype Engine · B + C, with A as a by-product

Chat's emote spam charges a meter; when it peaks, the streamer gets a "chat is popping off" moment on the overlay and the bot fires a flash poll into chat — the energy converts into participation.

Loop
Two closed loops sharing one state: viewer→overlay→streamer, and streamer→bot→viewers.
Signals
emotes[], message rate, command votes, POST /chat write-back.

Pros

  • Hedges A's one-way risk and C's originality risk at once
  • Reads as both insights and engagement
  • Demo peaks in under two minutes

Cons

  • ~2 extra integration hours over pure B
  • Two surfaces to keep coherent

Pick this if you can afford the integration cost — it's the strongest expected score per the four lenses.
