KICK chat data, at a glance

Compressed from docs.kick.com/events/event-types and docs.kick.com/apis/chat · Pairs with Lesson 0001

The one event that matters: chat.message.sent

Payload fieldSignal you can extract
contentRaw text (max 500 chars). Keywords, commands (!vote), sentiment heuristics. Emotes appear inline as [emote:4148074:HYPERCLAP].
emotes[]Pre-parsed emote IDs with string positions. Emote density / trending emotes with zero parsing work.
sender.identity.badges[]moderator, subscriber (count = months), sub_gifter (count = gifts). "Who's showing up" as structured data.
sender.identity.username_colorCosmetic — useful for rendering a faithful mock chat.
replies_toParent message + sender. Conversation threading; "what's landing".
created_atMessage-rate and hype-velocity windows.
message_idNeeded as reply_to_message_id when the bot replies.

Supporting events

EventUse it for
kicks.giftedHype moments — gift name, tier, amount, pinned_time_seconds. Natural meter boost.
channel.reward.redemption.updatedViewer participation with free-text user_input; status pending/accepted/rejected.
channel.followed / channel.subscription.*Audience-growth moments for a dashboard ticker.
livestream.status.updatedStream start/end — clean session boundaries for a demo script.
livestream.metadata.updatedTitle/category changes — visible when chat "shapes the stream".
moderation.bannedProbably skip today.

Mock-data rule of thumb

The brief requires mocks to reflect real KICK data. Copy the documented JSON shapes verbatim — field names, nesting, [emote:id:NAME] markup — and vary only the values. If a field isn't in the docs, don't invent it in the demo.
